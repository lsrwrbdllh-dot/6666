# نسخة أندرويد — محاسبة السوبر ماركت

تطبيق C# / .NET MAUI لأندرويد 8 أو أحدث، مع خادم ASP.NET Core وSQL Server. يستخدم الهاتف نفس قاعدة وإجراءات نسخة ويندوز. لا يحتاج الهاتف SQL Server؛ يحتاج إلى تشغيل API على جهاز المتجر أو خادم يستطيع الوصول إلى القاعدة.

نسخ APK والخادم ونتائج الاختبارات متاحة في [صفحة البناء](https://github.com/lsrwrbdllh-dot/6666/actions/runs/37550599597)؛ تفاصيلها في [حالة البناء](../BUILD-STATUS.md).

## الشاشات المتوفرة

الملخص، المنتجات والمخزون وحد المخزون، العملاء والموردون وأرصدة الأطراف، فواتير البيع والشراء، المصروفات وتمويل الصندوق والتحصيل والسداد، سجل العمليات والتفاصيل، ميزان المراجعة وقائمة الدخل ودفتر اليومية، ومشاركة الفواتير والتقارير CSV.

يدعم إدخال الباركود يدوياً أو عبر قارئ يعمل كلوحة مفاتيح، وليس مسح الكاميرا. يستخدم نفس قواعد منع المخزون والصندوق السالب ومعاملات SQL المتوازنة. لا يُدخل المخزون مباشرة؛ يُستلم عبر فاتورة شراء.

## تشغيل الخادم داخل المتجر

1. على جهاز Windows ثبّت .NET 10 SDK، وSQL Server وSSMS إن لم تكن موجودة.
2. إذا كانت قاعدة النسخة الأصلية جاهزة فلا تعِد تنفيذ Setup.sql. للبدء بقاعدة جديدة نفّذ `database/Setup.sql` مرة واحدة.
3. من PowerShell في مجلد المشروع اضبط الأسرار محلياً؛ لا تضفها إلى المستودع:

```powershell
dotnet user-secrets set "ConnectionStrings:Supermarket" "Server=.\SQLEXPRESS;Database=SupermarketAccounting;Integrated Security=True;Encrypt=True;TrustServerCertificate=True" --project src/Supermarket.Api
$storeApiKey = [Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
dotnet user-secrets set "ApiKey" $storeApiKey --project src/Supermarket.Api
$storeApiKey
```

4. احتفظ بالمفتاح وأدخله في تطبيق الهاتف. المثال يستخدم شهادة SQL المحلية للتطوير؛ استخدم شهادة موثوقة في التشغيل الفعلي.
5. شغّل `dotnet run --project src/Supermarket.Api --launch-profile LAN`.
6. اسمح للمنفذ TCP 5080 في جدار حماية جهاز الخادم لشبكة المتجر فقط. أوصل الهاتف والجهاز بنفس Wi-Fi. استخدم عنوان الجهاز داخل الشبكة، مثل `http://192.168.1.20:5080`، لا `localhost` أو `0.0.0.0`. في محاكي Android الافتراضي عنوان جهاز التطوير هو `http://10.0.2.2:5080`.
7. ثبّت APK التطوير، ثم افتح «إعداد الاتصال»، أدخل العنوان والمفتاح، واضغط «حفظ واختبار الاتصال».

اتصال HTTP متاح في APK **Debug** فقط للتجربة على شبكة موثوقة؛ المفتاح والبيانات لا تكون مشفرة أثناء النقل. للتشغيل الفعلي جهّز HTTPS واستخدم APK التشغيل. لا تستخدم بيئة Development على الإنترنت.

## تشغيل HTTPS

شغّل الخادم بوضع Production على HTTPS بشهادة موثوقة يثق بها Android، وأدخل سلسلة الاتصال والمفتاح عبر متغيرات البيئة `ConnectionStrings__Supermarket` و`ApiKey`. يمكن ضبط Kestrel عبر `Kestrel__Endpoints__Https__Url` و`Kestrel__Endpoints__Https__Certificate__Path` و`Kestrel__Endpoints__Https__Certificate__Password`. حساب تشغيل الخادم يحتاج صلاحيات قاعدة البيانات. النسخة الحالية لا تثق تلقائياً برؤوس الوكيل؛ عند استخدام reverse proxy اضبط ForwardedHeaders وقائمة الوكلاء الموثوقين أولاً بدلاً من تعطيل حماية HTTPS.

الهاتف يحفظ المفتاح في Android SecureStorage، ويمنع النسخ الاحتياطي للتطبيق. هذه مصادقة بمفتاح مشترك؛ ليست بديلاً لصلاحيات الموظفين وتسجيل الدخول الفردي. المفتاح يسمح بوظائف النظام؛ لا توزعه على أشخاص غير مخولين، ودوّره من الخادم والأجهزة عند الحاجة.

## بناء APK

مع .NET 10 SDK وAndroid SDK وJDK 21 مثبتة على جهاز التطوير:

```powershell
dotnet workload install maui-android
dotnet publish mobile/Supermarket.Android -c Debug -p:AndroidPackageFormats=apk
```

أو شغّل `Build-Android.cmd`. ملف `*-Signed.apk` يوجد تحت `mobile/Supermarket.Android/bin/Debug/net10.0-android/` أو مجلد `publish` تحته. للمحاكيات ومعمارية الجهاز تُستخدم إعدادات .NET Android الافتراضية.

لنسخة HTTPS استخدم `-c Release`. إعدادات التوقيع الافتراضية مخصصة للاختبار. للنشر الرسمي وقبل توزيع إصدار يعتمد عليه المستخدمون، أنشئ keystore خاصاً ومرر إعدادات `AndroidKeyStore` و`AndroidSigningKeyStore` و`AndroidSigningKeyAlias` و`AndroidSigningStorePass` و`AndroidSigningKeyPass` بشكل آمن؛ لا تحفظ المفاتيح أو كلمات المرور في Git.

## GitHub Actions

`Android and accounting checks` يبني API وملفات APK، ويشغّل اختبارات محاسبية وHTTP على SQL Server تجريبي منفصل. بعد نجاح التشغيل افتح Actions ثم التشغيل ثم Artifacts. الحزمة `supermarket-android-debug` لتجربة LAN، و`supermarket-android-https` لاتصال HTTPS، و`supermarket-api` لملفات الخادم، و`supermarket-windows` للنسخة الأصلية. تحتاج تفعيل Actions في المستودع إن كانت معطّلة. كلمة المرور والمفتاح الظاهران في workflow لقاعدة الاختبار المؤقتة فقط؛ ليست أسرار تشغيل فعلي.

## انقطاع الاتصال

قبل إرسال فاتورة أو حركة صندوق يُحفظ الطلب ومعرفه في SecureStorage. عند انقطاع الرد يبقى الطلب في «الملخص»، ويُرسل بنفس المعرف؛ إجراءات SQL تمنع ترحيله مرتين. لا تنشئ حركة بديلة قبل حل الطلب المعلق. إذا أكد الخادم رفض البيانات برمز 400 أو 409 يُزال الطلب لتصحيح البيانات. إذا أردت إزالة طلب غير محسوم، تحقق أولاً من سجل العمليات؛ فقد يكون حُفظ.

هذا دعم لاستعادة الطلب، وليس عملاً محاسبياً كاملاً دون الإنترنت. صفحات القوائم والتقارير تتطلب اتصالاً. سجل العمليات يعرض آخر 500 عملية للفترة، واليومية آخر 1000 سطر؛ قلّل الفترة للحصول على نطاق أصغر. عمليات إضافة المنتجات والأطراف ليست ضمن طابور الترحيل؛ بعد خطأ اتصال تحقق من القائمة قبل إعادة الإضافة.

## حدود النسخة

تشارك النسخة الأولية حدود نظام ويندوز: لا تشمل الضرائب والفوترة الإلكترونية والمرتجعات والخصومات والورديات والجرد والتسويات والدفعات وتواريخ الصلاحية. مشاركة تفاصيل العملية متاحة، أما طابعة الفواتير الحرارية ومسح الباركود بالكاميرا فيحتاجان إضافة خاصة. جميع المبالغ بعملة واحدة غير محددة. يلزم تشغيل فعلي على هاتف وخادم SQL واختبار الشبكة قبل استخدام البيانات الحقيقية.
