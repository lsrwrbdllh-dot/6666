# نظام محاسبة سوبر ماركت — ويندوز وأندرويد

نسخة أندرويد وخادم API متاحان؛ راجع [دليل أندرويد](mobile/README.md). تطبيق أندرويد مكتوب بـ C# / .NET MAUI ويستخدم نفس قاعدة SQL Server. تفاصيل نسخة ويندوز الأصلية أدناه.

مشروع C# / Windows Forms بواجهات عربية من اليمين إلى اليسار، وقاعدة بيانات SQL Server. ملفات المصدر جاهزة للمراجعة والبناء على ويندوز؛ لم يتم بناء ملف EXE أو إجراء اختبار تشغيل فعلي في البيئة السحابية الحالية.

## الوظائف

- تعريف المنتجات والباركود وأسعار البيع وحد المخزون وتعطيل المنتج.
- تعريف العملاء والموردين.
- فواتير بيع وشراء متعددة الأصناف: نقدي، آجل، أو دفع جزئي.
- إدخال باركود قارئ يعمل كلوحة مفاتيح مع Enter.
- تحديث المخزون ومتوسط التكلفة وقيمته الدفترية.
- تمويل الصندوق، المصروفات النقدية، تحصيل العملاء وسداد الموردين.
- دفتر اليومية، ميزان مراجعة تراكمي، قائمة دخل، أرصدة الأطراف وتنبيهات المخزون.
- سجل العمليات وتفاصيل الفواتير ومعاينة الطباعة وتصدير CSV بترميز عربي.

## متطلبات التشغيل على ويندوز

1. Windows 10 أو 11.
2. Visual Studio 2022 إصدار 17.8 أو أحدث، مع حزمة **.NET desktop development**، أو .NET 8 SDK.
3. SQL Server 2019 أو أحدث؛ SQL Server Express مناسب للبداية.
4. SQL Server Management Studio (SSMS).
5. اتصال بالإنترنت لاستعادة حزمة `Microsoft.Data.SqlClient` أول مرة.

## إنشاء القاعدة وتشغيل البرنامج

1. افتح SSMS واتصل بالخادم، مثلاً `.\SQLEXPRESS`.
2. افتح `database/Setup.sql` ونفذه **مرة واحدة** بحساب مخول بإنشاء قاعدة بيانات. السكربت ينشئ قاعدة `SupermarketAccounting` والجداول والإجراءات وثلاثة منتجات تجريبية بأرصدة صفرية. إعادة تشغيله على قاعدة مجهزة سيؤدي إلى أخطاء إنشاء؛ لا تستخدمه كترقية لقاعدة تحتوي بيانات.
3. افتح `SupermarketAccounting.sln` في Visual Studio ثم اضغط F5.
4. من «إعداد الاتصال» اكتب اسم الخادم والقاعدة. الاتصال يستخدم مصادقة Windows؛ يجب أن يكون حساب ويندوز الذي يشغّل البرنامج مخولاً على القاعدة.
5. في نسخة SQL Express المحلية ذات الشهادة الذاتية يمكن تفعيل «الثقة بشهادة الخادم المحلية». للخادم الفعلي استخدم شهادة موثوقة واترك الخيار غير مفعّل.
6. اضغط «اختبار وحفظ» ثم «تحديث البيانات».

من PowerShell، داخل مجلد المشروع:

```powershell
dotnet restore .\SupermarketAccounting.sln
dotnet build .\SupermarketAccounting.sln -c Release
dotnet run --project .\src\SupermarketAccounting
```

لإنتاج نسخة مستقلة لويندوز 64 بت:

```powershell
dotnet publish .\src\SupermarketAccounting -c Release -r win-x64 --self-contained true -o .\publish
```

الناتج `publish/SupermarketAccounting.exe`. SQL Server يبقى متطلباً منفصلاً.

## تجربة أولى

1. سجّل «تمويل الصندوق» بمبلغ 1000.
2. افتح فاتورة شراء: اختر المورد التجريبي، أضف 10 وحدات حليب بسعر شراء 3 للوحدة، ودفع كامل، ثم رحّل الفاتورة.
3. افتح فاتورة بيع: أضف وحدتين حليب بسعر بيع 5 للوحدة ودفع كامل، ثم رحّل.
4. يصبح مخزون الحليب 8 وحدات، وتكلفة المبيعات 6، وإيراد المبيعات 10، وصافي الربح 4، ورصيد الصندوق 980.
5. من سجل العمليات اختر الفاتورة ثم «تفاصيل العملية» لمعاينة الطباعة.
6. جرّب فاتورة بيع جزئية الدفع باسم العميل التجريبي، ثم «تحصيل من عميل» لتسوية الرصيد.

## القواعد المحاسبية

كل عملية ترحيل تتم داخل معاملة SQL واحدة تشمل الفاتورة والمخزون والقيد. يتم منع المخزون السالب، المدفوع الزائد، التحصيل أو السداد الأكبر من المستحق، وصرف نقد يتجاوز الصندوق. تمويل الصندوق يقابل حساب رأس المال. لا تعدّل الكميات مباشرة؛ استخدم الشراء لإدخال المخزون.

التكلفة تعتمد المتوسط المرجح، والقيم النقدية تقرّب إلى منزلتين والكميات إلى ثلاث. تحتفظ المنتجات بقيمة مخزون دفترية مستقلة؛ عند بيع آخر كمية تُحمّل كامل القيمة المتبقية على تكلفة المبيعات لتجنب بقاء فروق تقريب عند نفاد الصنف. قد يتغير متوسط التكلفة قليلاً بعد البيع بسبب التقريب.

إعادة محاولة الحفظ في **نفس نافذة العملية** تستخدم معرف طلب ثابتاً لمنع التكرار عند انقطاع الرد. بعد محاولة الترحيل تُقفل الحقول؛ أعد المحاولة أو أغلق النافذة. إذا أغلقتها بعد خطأ اتصال، تحقق من سجل العمليات قبل إنشاء فاتورة بديلة، لأن العملية قد تكون حُفظت. الفواتير المرحّلة غير قابلة للتعديل أو الحذف من الواجهة.

## الاختبارات وحالة التحقق

`database/Verify.sql` اختبار تكاملي يدوي: تمويل، شراء جزئي الدفع، بيع، إعادة طلب البيع، أرصدة العملاء والموردين، التحصيل والسداد، المصروف، توازن القيود ومنع البيع بلا مخزون. نفذه على قاعدة تطوير بعد `Setup.sql`. بيانات الاختبارات تُرجع عبر ROLLBACK؛ أرقام الهوية قد تتقدم.

لم تُشغّل هذه الاختبارات هنا. البيئة الحالية Linux ولا تحتوي .NET SDK أو SQL Server، ومحاولة تنزيل SDK لم تكتمل بسبب الاتصال. أُجريت مراجعة للملفات والتحقق من بنية المشروع وأرشيف التسليم؛ يجب إكمال البناء والاختبار على ويندوز قبل الاعتماد على البرنامج.

## حدود النسخة الحالية

هذه نسخة تأسيسية وليست إصداراً معتمداً للاستخدام التجاري. لا تتضمن حالياً ضريبة القيمة المضافة أو الفوترة الإلكترونية، الخصومات، المرتجعات، الصلاحيات حسب الموظف، الورديات، الجرد والتسويات، تواريخ الصلاحية والدفعات، أو وحدات متعددة للصنف. العملة غير محددة؛ كل المبالغ بعملة واحدة، والأسعار بلا ضريبة. يلزم تحديد البلد والعملة والمتطلبات الضريبية قبل إضافة تلك الميزات.

المصادقة تعتمد حساب Windows، ولا توجد شاشة دخول مستقلة. خزّن نسخ SQL Server الاحتياطية عبر أدوات الخادم. لا تحفظ قاعدة البيانات في مستودع المصدر. إعداد الاتصال محفوظ لكل مستخدم في `%LOCALAPPDATA%/SupermarketAccounting/connection.json` ولا يحتوي كلمة مرور. امنح مستخدمي التطبيق أقل صلاحيات لازمة بدلاً من صلاحيات مدير الخادم.

## الملفات

- `src/SupermarketAccounting`: الواجهات وطبقة الاتصال.
- `database/Setup.sql`: إنشاء قاعدة البيانات وإجراءات الترحيل.
- `database/Verify.sql`: سيناريو التحقق المحاسبي.
- `SupermarketAccounting.sln`: ملف الحل لبرنامج Visual Studio.
